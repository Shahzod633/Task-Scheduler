# Промпт для Antigravity: локальный аналог Trello под Windows 11

Скопируй всё содержимое ниже целиком в Antigravity как первое сообщение / task description.

---

## Задача

Создай нативное десктопное приложение под Windows 11 — локальный аналог Trello (канбан-доски с колонками и карточками), полностью работающее офлайн, без бэкенд-сервера, без сети. Все данные хранятся локально в SQLite.

## Технологический стек (обязательно)

- **Фреймворк приложения:** Tauri v2 (Rust backend + системный WebView2 на Windows)
- **База данных:** SQLite, файл `trello_clone.db` в стандартной директории данных приложения (`%APPDATA%/<app-name>/`), доступ через `rusqlite` или `sqlx`
- **Фронтенд:** чистые HTML5 / CSS3 / JavaScript (без тяжёлых фреймворков типа React/Vue — держим бандл минимальным), CSS Grid + Flexbox для лейаута
- **Drag-and-drop:** библиотека `Sortable.js` для перетаскивания карточек между колонками
- **IPC:** все операции чтения/записи (создание доски, колонки, карточки, перемещение карточки) идут через Tauri `invoke` команды в Rust, который пишет в SQLite. Никакой логики хранения на фронтенде — фронт только рендерит state, полученный от бэкенда.

**Производительность (ориентир, не жёсткая гарантия):** минимизировать RAM footprint насколько позволяет связка Tauri+WebView2 (реалистично ожидать это ниже, чем у аналогичного Electron-приложения, но не гарантировать конкретное число МБ). Холодный старт — за доли секунды, без загрузки тяжёлых фреймворков на старте.

## Дизайн-система

- Название приложения и логотип — свои, не Trello (я подставлю название/логотип сам, в промпте оставь плейсхолдер `<APP_NAME>` и место под свою иконку/лого вместо логотипа Trello везде в UI — шапка, about-окно, иконка exe).
- Тёмная тема в духе Windows 11: основной фон `#181a1f`/`#1d1f24`, сайдбар чуть темнее фона для визуальной иерархии.
- Карточки — полупрозрачные тёмные подложки, `border-radius: 8–12px`.
- Акцентный цвет для ключевых кнопок и градиентов на превью досок — **сделай это настраиваемой CSS-переменной** `--accent-color`, не хардкодь фирменный синий Trello (`#0079bf`) напрямую — я подберу свой оттенок сам, потом просто поменяю значение переменной.
- Системный шрифт без засечек, высокий контраст белого текста на тёмном фоне.
- В остальном визуально ориентируйся на Trello-подобный тёмный интерфейс Windows 11 как описано ниже — я внесу лёгкие точечные правки (цвет акцента, название, логотип) сам после генерации, глубоко перерабатывать структуру и лейаут не нужно.

## Экраны и функциональность

### Экран А — Главный хаб (Workspace & Dashboard)
- Верхняя панель: логотип/название приложения слева, широкая строка поиска по центру (фильтрует доски по названию в реальном времени), кнопка «+ Создать» (акцентный цвет), справа — колокольчик уведомлений, справка, аватар пользователя.
- Левый сайдбар: разделы «Доски», «Шаблоны», «Главная страница»; блок «Рабочие пространства» со списком пространств.
- Центральная зона: сетка карточек досок (у каждой — превью-градиент и название), отдельная интерактивная карточка «Создать доску» с подсвечивающейся при наведении рамкой.
- Опционально: блок шаблонов сверху (можно закрыть крестиком) — не приоритет первой версии.

### Экран Б — Управление рабочим пространством
- Раскрывающееся подменю в сайдбаре под названием пространства: «Доски» (активный пункт подсвечен), «Участники» (+ кнопка добавления), «Настройки» (шестерёнка), «Оплата» — этот пункт можно скрыть/убрать, т.к. приложение не имеет подписочной модели.
- Шапка пространства: название с иконкой редактирования (карандаш), метки статуса/видимости (например «Приватная» с иконкой замка).
- Кнопка «Посмотреть закрытые доски» — доступ к архиву удалённых/архивированных досок (soft-delete в SQLite, не hard-delete).

### Экран В — Активная Kanban-доска (главный экран приложения)
- Верхняя панель доски: название доски слева, переключатель представлений; справа — Power-Ups (заглушка/опционально), автоматизация (заглушка/опционально), фильтры, избранное (звёздочка), приватность (замок), «Поделиться» (для локального приложения можно сделать экспорт доски в JSON/файл), меню «...».
- Колонки (Kanban columns): вертикальные скруглённые блоки с тёмным фоном.
  - Каждая колонка: заголовок, счётчик карточек, список карточек, кнопка `+ Добавить карточку` внизу.
  - Карточка может содержать: заголовок, описание, чек-лист (опционально), метки/цвета, дедлайн (опционально).
  - Крайний элемент справа в ряду колонок — кнопка `+ Добавьте ещё одну колонку`, при клике открывает инлайн-поле ввода названия, сразу сохраняет новую колонку в SQLite через Tauri IPC.
- Drag-and-drop карточек между колонками через Sortable.js, с сохранением нового порядка/колонки в SQLite при каждом drop.
- Drag-and-drop для изменения порядка самих колонок — тоже через Sortable.js.

### Экран Г — Плавающая нижняя панель (Floating Dock)
- Компактный полупрозрачный бар с blur-эффектом внизу экрана поверх доски.
- Кнопки: Inbox (папка), Планировщик (календарь), Доска (активный режим, синий индикатор снизу), «Выбрать другую доску» (возврат в хаб — Экран А).

### Опционально (второй приоритет, если базовый функционал стабилен)
- Split-view: одновременный показ Inbox и Календаря рядом с доской через CSS Grid, с drag-and-drop задач между ними.

## Пользовательские сценарии (User Flows)

1. Запуск приложения → пользователь видит Экран А (хаб) → клик по карточке доски → мгновенный переход на Экран В (доска) с плавающим доком (Экран Г).
2. Клик «Выбрать другую доску» на доке → возврат на Экран А.
3. Добавление колонки → инлайн-инпут → сохранение в SQLite → колонка сразу появляется без перезагрузки UI.
4. Перетаскивание карточки между колонками → обновление `column_id` и `position` карточки в SQLite.

## Схема данных SQLite (предложи и создай сам, ориентир)

Таблицы: `workspaces`, `boards`, `columns` (с полем `position` для порядка), `cards` (с полями `column_id`, `position`, `title`, `description`, `created_at`, `archived`), опционально `labels`, `card_labels`.

## Что нужно от Antigravity в результате

1. Полностью рабочий Tauri v2 проект (структура `src-tauri/` + `src/` фронтенда), готовый к сборке под Windows 11 (`.msi`/`.exe` через `tauri build`).
2. Rust-команды (Tauri commands) для CRUD-операций над workspaces/boards/columns/cards, с миграцией схемы SQLite при первом запуске.
3. Фронтенд, реализующий все четыре экрана выше со стилями по описанной дизайн-системе.
4. Интеграция Sortable.js для drag-and-drop карточек и колонок.
5. Инструкция по запуску в dev-режиме (`tauri dev`) и сборке релиза (`tauri build`) под Windows.

Начни с настройки проекта (Tauri init + SQLite миграции + базовая Rust-command-обвязка), затем переходи к Экрану В (доска) как к ядру приложения, и только потом — к Экранам А, Б, Г.
