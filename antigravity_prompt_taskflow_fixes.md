# Промпт для Antigravity: доработка TaskFlow (исправление нерабочих элементов + новый функционал)

Контекст для агента: это Tauri v2 + Rust + SQLite десктоп-приложение под Windows 11, локальный аналог Trello под названием **TaskFlow**. Базовая структура (хаб, доски, колонки, карточки, плавающий док) уже сгенерирована и запускается, но значительная часть интерфейса — нерабочие заглушки, а роутинг дублирует один и тот же экран вместо разных страниц. Ниже — точное описание того, как каждый элемент должен работать, а не просто список того, что сломано. Реализуй именно это.

---

## 1. Верхняя правая группа кнопок (глобальный хедер, видна на всех экранах)

Сейчас: колокольчик, «?», аватар «TF» — некликабельны.

Как должно быть:
- **Колокольчик (уведомления):** клик открывает выпадающую панель (`position: absolute`, привязана к иконке) шириной ~320px. Если уведомлений нет — состояние «Нет новых уведомлений» с приглушённым текстом. Список уведомлений храни в отдельной SQLite-таблице `notifications` (`id`, `title`, `body`, `created_at`, `read`), генерируй уведомление минимум в одном реальном сценарии — например, при пометке карточки как ошибки (см. п.5).
- **Знак вопроса (справка):** клик открывает небольшое модальное окно/попап со статическим списком: горячие клавиши приложения, ссылка «О программе» (версия, ссылка на репозиторий — можно оставить плейсхолдер).
- **Аватар «TF»:** клик открывает модальное окно профиля со следующими полями, редактируемыми и сохраняемыми в SQLite (таблица `user_profile`, singleton-строка):
  - Инициалы/аватар (текстовое поле, 1–2 символа, отображается в кружке вместо «TF»)
  - Отображаемое имя
  - Переключатель темы (пока можно оставить только тёмную, но сам toggle должен физически существовать и сохранять выбор)
  - Кнопка «Сохранить», которая реально пишет в БД и сразу обновляет аватар в хедере без перезапуска приложения.

## 2. Верхняя навигация: «Пространства», «Недавние», «Избранное»

Сейчас: элементы декоративные, никуда не ведут.

Как должно быть — три разных поведения, не путать между собой:
- **«Пространства»** — клик открывает выпадающий список всех рабочих пространств пользователя (из таблицы `workspaces`) с возможностью переключиться на любое (переключение обновляет активное пространство в сайдбаре и на главном экране) и пунктом «+ Создать пространство» внизу списка.
- **«Недавние»** — отдельная страница (см. роутинг в п.3) со списком последних открытых досок в хронологическом порядке. Веди таблицу `board_recent_views` (`board_id`, `opened_at`) и пиши в неё запись при каждом открытии доски.
- **«Избранное»** — отдельная страница со списком досок, у которых `is_favorite = 1` (используй существующее поле звёздочки на карточке доски — судя по скриншоту, оно уже есть у доски «Отслеживание ошибок»). Клик по звёздочке на карточке доски в хабе должен переключать `is_favorite` и сразу обновлять эту страницу.

## 3. Роутинг: сайдбар и нижний плавающий док

Сейчас: «Доски», «Шаблоны», «Главная страница» в сайдбаре и «Inbox», «Планировщик», «Доска», «Выбрать другую доску» в доке — либо не работают, либо показывают один и тот же экран списка досок.

Реализуй настоящую SPA-архитектуру на фронте (простой роутер на чистом JS, без фреймворков — например, объект-состояние `currentView` + функция `renderView(view)`, которая полностью перерисовывает контент центральной зоны). Экраны:

| Элемент | Экран | Содержимое |
|---|---|---|
| Сайдбар → «Доски» | Хаб текущего пространства | Сетка досок (текущее поведение — оставить) |
| Сайдбар → «Шаблоны» | Страница шаблонов | Список заготовок досок (например «Kanban», «Отслеживание ошибок», «Управление проектами») — клик по шаблону создаёт новую доску с предзаполненными дефолтными колонками этого типа |
| Сайдбар → «Главная страница» | Домашняя сводка | Виджет «Недавние доски» (3–5 штук) + виджет «Мои задачи-ошибки за неделю» (см. п.5, можно как маленький превью графика) |
| Сайдбар → «Настройки» | Страница настроек | Форма редактирования пространства (название, приватность), плюс профиль пользователя (дублирует модалку из п.1 полноэкранно) |
| Док → «Inbox» | Отдельная страница | Список карточек без назначенной доски/колонки — быстрый инбокс задач, из него можно перетащить/назначить задачу в конкретную доску |
| Док → «Планировщик» | Отдельная страница | Календарное представление карточек, у которых задан дедлайн (добавь полю `cards.due_date`, если его ещё нет) |
| Док → «Доска» | Текущая активная канбан-доска | Как сейчас, без изменений |
| Док → «Выбрать другую доску» | Возврат в Хаб | Как сейчас |

Важно: у каждого пункта должен быть свой явный active-state (подсветка), и переключение между ними не должно перезагружать всё приложение — только контент центральной зоны.

## 4. Доски, колонки, карточки

Сейчас: карточки при перемещении между колонками, судя по описанию, удаляются и пересоздаются, а не обновляются.

Исправь:
- **Дефолтные колонки при создании новой доски** (не из шаблона, обычная кнопка «Создать доску»): создавай автоматически 4 колонки с названиями **«Новые»**, **«В работе»**, **«На проверке»**, **«Готово»** (это перевод твоих «To Do / Working / Upcoming / Finished» — держи UI полностью на русском языке, не смешивай языки в одном интерфейсе). Пиши их в таблицу `columns` с `board_id` новой доски и `position` 0–3 сразу в рамках одной транзакции создания доски.
- **Перемещение карточки между колонками** (drag-and-drop через Sortable.js): при `onEnd`-событии вызывай **один** Tauri-command `update_card_position(card_id, new_column_id, new_position)`, который делает `UPDATE cards SET column_id = ?, position = ? WHERE id = ?`. Никакого delete+insert. Также при перемещении карточки в пределах одной колонки — пересчитывай `position` только у затронутых соседних карточек, не у всех карточек доски.
- Убедись, что счётчик карточек у каждой колонки (`0` на скриншотах) реактивно обновляется после каждого перемещения/создания/удаления карточки без ручного обновления страницы.

## 5. Система отслеживания ошибок (сквозная, автоматическая)

Сейчас: судя по скриншотам, «Отслеживание ошибок» — это просто обычная доска-шаблон с колонками, которую нужно вести руками. Это не то, что нужно.

Как должно быть — глобальный механизм, не привязанный к одной доске:
- Добавь в таблицу `cards` поля: `is_mistake BOOLEAN DEFAULT 0`, `mistake_marked_at DATETIME NULL`, `mistake_resolved_at DATETIME NULL`.
- На любой карточке в любой доске, в любом пространстве, в контекстном меню карточки (или через «...» на самой карточке) добавь пункт **«Отметить как ошибку»**. При клике: `is_mistake = 1`, `mistake_marked_at = now()`, плюс создаётся запись в `notifications` (см. п.1).
- На карточке, уже помеченной как ошибка, пункт меняется на **«Ошибка исправлена»** — по клику пишет `mistake_resolved_at = now()` (карточка остаётся помеченной как mistake, но с датой закрытия — это нужно для аналитики динамики).
- Создай отдельный раздел **«Отслеживание ошибок»** (переименуй/замени текущую доску-шаблон на настоящий сквозной экран, доступный из сайдбара или из хаба отдельным пунктом) — это НЕ канбан-доска, а аналитический дашборд:
  - Список всех карточек с `is_mistake = 1` по всем доскам пространства, с указанием, из какой доски/колонки карточка, дата пометки, дата исправления (если есть), статус («Открыта» / «Исправлена»).
  - Диаграмма частоты: количество новых ошибок по неделям/дням за последние 30 дней (bar chart).
  - Диаграмма динамики решения: линия открытых ошибок во времени и линия закрытых ошибок во времени (line chart), либо среднее время между `mistake_marked_at` и `mistake_resolved_at`.
  - Для графиков используй лёгкую JS-библиотеку для графиков, **включённую в проект локально** (файл в `src/vendor/`), а не через CDN — приложение работает офлайн, подключение к интернету на рантайме недопустимо. Chart.js в виде локального `.js`-файла подходит.

## Общее техническое требование по всей доработке

- Все новые Tauri-команды должны быть добавлены в существующий `#[tauri::command]`-модуль и зарегистрированы в `invoke_handler`, без дублирования уже существующих команд создания/чтения досок и карточек.
- Любое изменение схемы SQLite делай через миграцию (добавляемую таблицу/поле создавай через `ALTER TABLE` / `CREATE TABLE IF NOT EXISTS` при старте приложения), чтобы у пользователей с уже существующей `trello_clone.db` (или как она теперь называется в TaskFlow) данные не терялись.
- Проверь и почини кликабельность каждого перечисленного элемента вручную — открой приложение, пройди по каждому пункту 1–5 и убедись, что клик действительно меняет видимое состояние экрана, а не проглатывается.

Начни с п.3 (роутинг) — это основа, без неё остальные пункты физически некуда вешать. Затем п.1 и п.2 (хедер), затем п.4 (drag-and-drop фикс — это баг, а не фича, приоритет высокий), и в конце п.5 как самый крупный новый функционал.
